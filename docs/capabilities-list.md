# Capability list

Fixed before any cell of the matrix was filled (see `capabilities.md`). A capability is a thing a team building the pet shop might want from the framework itself, not from a third-party package. Each is answered yes, partial or no per framework, with a link to that framework's own documentation, or "not documented".

1. Models with many-to-one relations
2. Migrations generated from models
3. Admin interface generated from models
4. Per-model admin permissions
5. User accounts with hashed passwords
6. Session (cookie) login
7. Token (bearer) authentication for APIs
8. JSON API generated from models
9. Request validation
10. CSRF protection
11. HTML templating
12. Pagination helper
13. Query filtering helper
14. Caching layer
15. Background jobs or scheduler
16. Internationalisation
17. Rate limiting
18. Email sending
19. WebSockets
20. OpenAPI document generation
21. Test tooling for the framework's own handlers
22. Project scaffolding command
